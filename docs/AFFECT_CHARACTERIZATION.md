# Affect and drive characterization (CP-A.1 -> CP-A.2)

Generated by `tools/affect_probe.py`. Every number below comes from that
script driving `AffectEngine`, `BoredomDrive`, `CompetenceTracker` and
`RelationalDrive` directly with a synthetic clock — no daemon, no store,
no wall-clock sleep. Re-run `python tools/affect_probe.py` from the repo
root to regenerate this file; nothing here is hand-typed.

**What changed since CP-A.1:** that checkpoint measured the engines and
found the coupled emotion/mood relaxation did not agree across tick rates
(a Jacobi/operator split, not a solution of the coupled system) and that
BoredomDrive's idle pressure was unbounded. CP-A.2 fixed both —
`AffectEngine._step` is now the exact solution of the coupled 2x2 system,
`BoredomDrive.update`'s idle branch now approaches a bounded ceiling — and
raised `MAX_TICK_DT_SECONDS` from 0.1 to 600 on the evidence in
"Clamp safety" below. Every table is regenerated against the current code,
so this document now shows the fixed system's numbers, not CP-A.1's; the
prose still points out where a table's shape changed and why.

This document measures; it does not itself change any integrator. See
`lyra_ai/DECISIONS.md` (CP-A.1 and CP-A.2 sections) for the scope both
checkpoints were produced under.

**The four agree** (spread below 1e-9 on every axis) at this span. This is
CP-A.2's fix: `AffectEngine._step` evaluates the coupled system's own
closed-form solution at t=dt, so running the same span in 36000 steps of
0.1, 60 steps of 60, or a single step of 3600 is the same formula evaluated
at the same t — not four different discretizations of it. CP-A.1 measured
a spread of 0.4-0.5 on these same axes, at this same span, with the old
Jacobi-split integrator (see the git history of this document, or
`lyra_ai/DECISIONS.md`'s CP-A.1 section, for that baseline).

Step-by-step at dt=60 (CP-A.1's swap case: with the old Jacobi split,
`emotion_decay=2.0` gave relax fraction `1-e^(-2*60)` ~= 1.0 and
`mood_drift=0.2` gave `1-e^(-0.2*60)` ~= 0.9999938, so the pair nearly swapped
values every step instead of converging). With the exact solve, the same
dt=60 steps now converge monotonically toward the shared equilibrium:

| step | t (s) | emotion.valence | mood.valence |
|---:|---:|---:|---:|
| 0 | 0 | -0.6 | -0.2 |

Both variables move monotonically toward the shared equilibrium (-0.236364, the tau-weighted average of the start values) and stay
there — no swapping, no oscillation. This is the done-when CP-A.2 named
directly: "the one-hour-at-dt=60 case converges toward mood instead of
returning to its starting value."

## Clamp safety (evidence for MAX_TICK_DT_SECONDS)

The daemon ticks once per turn, so an idle gap of any length — 8 minutes or
8 hours — collapses to exactly ONE tick at `dt = min(elapsed, MAX_TICK_DT_SECONDS)`.
The worst case for that one tick is boredom pressure already at its ceiling
(long prior idling) when the gap begins. For each candidate clamp value, one
tick at that dt, from a saturated-pressure start:

| candidate MAX_TICK_DT_SECONDS | pressure | emotion.valence | emotion.arousal | saturated? |
|---:|---:|---:|---:|---|
| 60 | 0.02 | -0.0234711 | 0.0117355 | False |
| 90 | 0.02 | -0.0343802 | 0.0171901 | False |
| 120 | 0.02 | -0.0452893 | 0.0226446 | False |
| 180 | 0.02 | -0.0671074 | 0.0335537 | False |
| 300 | 0.02 | -0.110744 | 0.0553719 | False |
| 600 | 0.02 | -0.219835 | 0.109917 | False |
| 900 | 0.02 | -0.328926 | 0.164463 | False |
| 1200 | 0.02 | -0.438017 | 0.219008 | False |

`600` is the value in `config.py`: large enough to cover every gap this
checkpoint's done-when calls "ordinary" (5 s, 60 s, 10 min — verified against a
live daemon, not just this table) without clamping, while the single-tick worst
case above stays clearly under saturation. Candidates past it in this table
saturate — that is exactly why the clamp is not larger; the table is the
evidence, not a guess.

The 3c (coupled) rows are not at floating-point-level agreement like 3a/3b:
BoredomDrive's pressure is exactly tick-rate invariant on its own, but
feeding it into AffectEngine still treats pressure as constant across each
step (item 1/3's design), so a run with fewer, larger steps samples the
pressure ramp from 0 to its ceiling — which takes only about
`ceiling/idle_rate` ~= 0.2 s — more coarsely
than a run with many small steps. That difference feeds `S` (see affect.py's
`_step` docstring), which has no decay of its own, so the small quantization
in how well each rate resolves that one brief ramp becomes a PERMANENT,
constant offset, not a growing one: the coupled rows above show ~5.6e-05
divergence at every span from 60 s to 8 h alike, not a value that grows with
span the way CP-A.1's did. That is the qualitative fix this checkpoint made
to the coupled path — bounded and flat instead of unbounded and accelerating —
even though it is not literally zero the way the uncoupled measurements are.

## dt consumption sites

Every place `dt` is used to advance state, by file and line, classified as
closed-form (exact for any dt on its own) or explicit Euler (first-order,
exact only in the dt -> 0 limit or when the rate has no state feedback):

| file:line | code | class | note |
|---|---|---|---|
| `lyra_ai/lyra_core/affect.py:121` | `relax = 1.0 - math.exp(-r * dt)` | closed-form | exact relaxation fraction for the coupled pair's difference channel D=e-m, at combined rate r=emotion_decay+mood_drift |
| `lyra_ai/lyra_core/affect.py:126` | `d1 = d0 * (1.0 - relax) + (forcing / r) * relax` | closed-form | D relaxed exactly toward its forced offset forcing/r; forcing held constant over this one step |
| `lyra_ai/lyra_core/affect.py:127` | `s1 = s0 + k_m * forcing * dt` | closed-form | S=k_m*e+k_e*m has no restoring term, so this is exact for constant forcing over the step, not an approximation |
| `lyra_ai/lyra_core/affect.py:99` | `self._encourage_remaining = max(0.0, self._encourage_remaining - dt)` | explicit Euler | linear countdown; exact regardless of step size because the rate has no state feedback (a floor clamp can still make it path-dependent near expiry) — out of CP-A.2's scope (not part of the emotion/mood coupling or the drive-to-affect path) |
| `lyra_ai/lyra_core/drives.py:126` | `self._pressure = max(0.0, self._pressure - self._relief_rate * dt)` | explicit Euler | relief branch, unchanged by CP-A.2 (item 2 named only idle accumulation); already bounded at 0 by the floor and now also bounded above by the idle branch's ceiling |
| `lyra_ai/lyra_core/drives.py:136` | `relax = 1.0 - math.exp(-k * dt)` | closed-form | CP-A.2: idle accumulation is now exact exponential approach to _BOREDOM_PRESSURE_CEILING (k=idle_rate/ceiling), replacing the old unbounded `pressure += idle_rate*dt` |
| `lyra_ai/lyra_core/drives.py:184` | `self._elapsed += dt` | explicit Euler | pure clock accumulation; exact regardless of step size since it sums to wall time by construction |

Temperament, over 36000 ticks at dt=0.1 across the same
span: delta(valence)=0, delta(arousal)=0, delta(control)=0.
Unchanged. `update()` never writes `_accum_rate`/`_emotion_decay`/`_mood_drift`;
only `AffectEngine.__init__`/`from_dict` set them. So temperament is not a
third *timescale* in the running system at all — it is a fixed parameter set
once at construction (or restore) and never advanced by `tick()`. "Three
timescales" as currently measured is two dynamic ones (emotion, mood) plus
one static one (temperament), not three rates of the same kind.

Unlike CP-A.1 (where these numbers reflected genuine trajectory divergence —
the coupled pair actually evolved differently at each dt), the underlying
trajectory is now identical at every dt (3a's agreement check). Any remaining
difference in the table above is purely the sampling grid: tau is measured by
scanning the trace at whatever dt produced it, so a coarser dt can only report
a crossing time rounded up to its own step size, not a different crossing.
